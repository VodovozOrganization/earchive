# Распознавание QR-кодов (WeChat QRCode)

Для QR-кодов на сканах УПД используется движок **WeChat QRCode** из OpenCV
(`opencv_contrib/wechat_qrcode`), который устойчивее к шумам печати, низкому
контрасту и перекосу скана, чем ZXing.

Есть два режима:

1. **Локальный (основной)** — модель загружается прямо в процесс `earchive`,
   без gRPC и без обращений к хосту.
2. **Сервисный (необязательный)** — отдельный x64-сервис, если локальный
   OpenCV по каким-то причинам нельзя поставлять вместе с приложением.

## Локальный режим

`earchive` собирается под **x86 / .NET Framework 4.6.1**, а пакет
`OpenCvSharp4.runtime.win` версии **4.8.0** содержит нативную сборку OpenCV
и для **win-x86**, и для win-x64. Поэтому WeChat QR можно грузить
непосредственно в процесс приложения:

- managed-обёртка — `OpenCvSharp4` 4.8.0;
- нативная библиотека — `dll\x86\OpenCvSharpExtern.dll` (~42 МБ);
- модели — каталог `QrModels` рядом с `earchive.exe`
  (`detect.prototxt`, `detect.caffemodel`, `sr.prototxt`, `sr.caffemodel`,
  `LICENSE`).

Модель инициализируется лениво при первом сканировании (около 0,8 с),
дальше распознавание занимает ~150–300 мс на страницу. Сетевые запросы
не выполняются.

Локальный распознаватель находится в
`Source/earchive/Recognaze/WeChatQrScanner.cs`, модели —
в `Source/earchive/QrModels`.

Порядок работы `QRCodeRecognizer`:

1. локальный WeChat QR;
2. если локальный OpenCV/модель недоступны — gRPC-сервис (если настроен);
3. если недоступны оба — прежний ZXing.

Штрих-коды по-прежнему распознаются локально через ZXing и к QR-движку
не относятся.

## Что делает распознаватель

Для каждой страницы последовательно пробует несколько вариантов изображения
и останавливается на первом успешном:

1. страница целиком;
2. область в правом верхнем углу (где обычно расположен QR-код УПД);
3. та же область с повышением контраста (CLAHE);
4. повороты области на −3…+3° (перекос скана);
5. повышение резкости;
6. бинаризация Оцу и увеличение ×2 (бледная печать).

На тестовом наборе из 10 сканов (8 страниц с QR-кодом) распознаны все
8 QR-кодов, в том числе проблемные страницы 08 и 10. Локальный ZXing на этих
же сканах не распознал ни одного.

## Необязательный gRPC-сервис

Сервис нужен только если локальную нативную библиотеку нельзя поставлять
на рабочие места. Он собирается под **net5.0** (generic host, `Program` +
`Startup`) и работает отдельным **x64**-процессом.

### Требования

- Windows x64;
- .NET 5 Runtime (5.0.x);
- Visual C++ Redistributable 2015–2022 (нужен для OpenCV).

.NET 5 и .NET 6 сняты с поддержки Microsoft. Если политика позволяет,
предпочтительнее `net8.0` (LTS); для перехода достаточно поменять
`<TargetFramework>` в `QrRecognitionService.csproj`.

### Сборка и запуск

```powershell
msbuild Source\earchive\QrRecognitionService\QrRecognitionService.csproj `
  /t:Restore,Build /p:Configuration=Release

Earchive.QrRecognition.Service.exe --urls http://0.0.0.0:5107
```

Порт по умолчанию — `5107` (задан в `appsettings.json`). Модели берутся из
общего каталога `Source/earchive/QrModels` и копируются в `Models` рядом
с сервисом.

### Настройка приложения на сервис

Параметры читаются из `base_parameters`:

| Параметр | Назначение | Пример |
| --- | --- | --- |
| `qr_grpc_address` | Хост сервиса | `192.168.0.10` |
| `qr_grpc_port` | Порт сервиса | `5107` |
| `qr_grpc_use_tls` | Использовать HTTPS (`true`/`false`) | `false` |

Сервис используется только если локальный распознаватель недоступен.
Если параметры не заданы, приложение вообще не создаёт gRPC-клиент и
работает полностью локально.

Для HTTPS настройте Kestrel-сертификат стандартными средствами ASP.NET Core
(`Kestrel:Endpoints:Https` в `appsettings.json`) и установите
`qr_grpc_use_tls = true`.

## Протокол

Контракт описан в `Source/earchive/Recognaze/Protos/earchive_qr.proto`
(сервис `earchive.qr.QrRecognition`, метод `Recognize`). На запрос передаётся
изображение страницы, в ответе — список текстов найденных QR-кодов.
